# Local MCP server

The optional MCP server lets a compatible host discover and run bounded local
framework checks through the official Python MCP SDK. It uses stdio: the host
starts the process, and no MCP network listener is opened. Offline checks are
available directly. To share browser-configured target/provider connections,
use the console bridge described below; its fixed checks can contact the network.

## Standalone setup

Linux users can also use `./api-lab mcp-setup --format claude` or
`./api-lab mcp-setup --format codex` after core setup. See the
[Linux launcher guide](LINUX_LAUNCHER.md).

First install the framework in a sandbox virtual environment as described in the
[README](../README.md). From that active environment:

```bash
python scripts/setup_mcp.py --format claude
# Or generate the Codex configuration:
python scripts/setup_mcp.py --format codex
```

The helper creates a separate SDK environment beneath
`~/sandbox/enterprise-api-testing-framework/mcp/` and prints Claude JSON or Codex
TOML. Copy the configuration into your host's MCP settings, then restart or
reconnect the host. Omitting `--format` preserves the Claude JSON default.
Installation progress goes to stderr so stdout contains only the configuration.
The first setup requires package-registry access; already installed matching SDK
environments are reused. `--sandbox` and `--data-dir` select other directories
beneath `~/sandbox`.

The SDK uses a newer Pydantic than the framework's pinned contract baseline.
Its requirements are intentionally isolated. Do not install
`requirements-mcp.txt` together with the core requirements in one environment.
Generated configuration contains your machine's paths: keep it local. A
Claude Desktop placeholder example is:

```json
{
  "mcpServers": {
    "api-testing-framework": {
      "command": "/path/to/sandbox/mcp/venv/bin/python",
      "args": [
        "/path/to/checkout/scripts/mcp_server.py",
        "--runner-python", "/path/to/sandbox/framework/venv/bin/python",
        "--data-dir", "/path/to/sandbox/control"
      ],
      "env": {"PYTHONDONTWRITEBYTECODE": "1"}
    }
  }
}
```

The setup helper generates the correct Python executable path for the platform.
Windows paths, spaces and quotes are escaped in the selected format. This
repository does not edit any host's configuration automatically.

## Claude Code

Use the generated command and args with Claude Code's stdio registration. The
following command contains placeholders; replace them with the generated paths:

```bash
claude mcp add --transport stdio --scope local api-testing-framework -- \
  "/path/to/sandbox/mcp/venv/bin/python" \
  "/path/to/checkout/scripts/mcp_server.py" \
  --runner-python "/path/to/sandbox/framework/venv/bin/python" \
  --data-dir "/path/to/sandbox/control"
```

Run registration yourself if you want it; setup prints configuration only. Use
your host's tool controls to decide when checks can execute. See the official
[Claude Code MCP guide](https://code.claude.com/docs/en/mcp).

## Codex

`python scripts/setup_mcp.py --format codex` prints TOML in this shape:

```toml
[mcp_servers.api-testing-framework]
command = "/path/to/sandbox/mcp/venv/bin/python"
args = ["/path/to/checkout/scripts/mcp_server.py", "--runner-python", "/path/to/sandbox/framework/venv/bin/python", "--data-dir", "/path/to/sandbox/control"]

[mcp_servers.api-testing-framework.env]
PYTHONDONTWRITEBYTECODE = "1"
```

Alternatively, register the same placeholder launch command through the CLI:

```bash
codex mcp add api-testing-framework -- \
  "/path/to/sandbox/mcp/venv/bin/python" \
  "/path/to/checkout/scripts/mcp_server.py" \
  --runner-python "/path/to/sandbox/framework/venv/bin/python" \
  --data-dir "/path/to/sandbox/control"
```

Keep generated machine paths local and merge configuration with existing host
settings rather than replacing them. See the official
[Codex MCP guide](https://learn.chatgpt.com/docs/extend/mcp).

The offline MCP operations require no model API key. Optional Connections checks
use separately configured target/provider credentials through the console bridge.
Claude or Codex manages its own account authentication separately. No model text
is generated by this server, and setup does not sign in or modify either host's
settings.

## Share the console session from VS Code

The optional `./api-lab mcp-setup --console --format codex` (or `claude`) prints
bridge configuration. Keep the console running and use its same sandbox options.
For direct setup, add `--console-state /path/to/sandbox/desktop/checkout/state.json`
to `scripts/setup_mcp.py`. See [Connections](CONNECTIONS.md) for credential lifetime
and supported target/provider checks. The bridge shares browser-configured
profiles; standalone MCP has a separate memory session. Neither mode edits host
settings, signs in, or accepts credentials through tools.

For the bridge, the generated launch arguments replace `--runner-python` and
`--data-dir` with `--console-state` and the launcher's private state-file path.
A placeholder Codex example is:

```toml
[mcp_servers.api-testing-framework]
command = "/path/to/sandbox/mcp/venv/bin/python"
args = ["/path/to/checkout/scripts/mcp_server.py", "--console-state", "/path/to/sandbox/desktop/checkout/state.json"]

[mcp_servers.api-testing-framework.env]
PYTHONDONTWRITEBYTECODE = "1"
```

Claude JSON uses the same `command`, `args` and `env` values under
`mcpServers.api-testing-framework`. Generate the selected format instead of
copying a placeholder unchanged. The bridge reads only a state file beneath
`~/sandbox` and sends its local session token only to the specified loopback
console. API keys stay in that console process, rather than in host configuration.
Closing the browser tab leaves it running; stopping it makes bridge calls fail
until the console is started again. This is a stdio MCP integration, not a new
VS Code extension. Actual authenticated host sessions require separate validation.

## Tools

| Tool | Purpose |
|---|---|
| `capabilities` | List available operations and concurrency limits. |
| `list_runs` | List sanitized run metadata and result summaries. |
| `start_run` | Start an offline operation or a configured `target`, `openai`, `anthropic` check; receive a run ID. |
| `connections` | Read configured flags without credentials or URLs. |
| `get_run` | Poll that run ID until the status is terminal. |

For example: “Show the available checks, run the contract baseline, and tell me
its final result.” Starting a run is not evidence of success; inspect the final
status and summary. One operation runs at a time. The evaluation operation uses
the supplied synthetic response corpus and calls no model provider.

The five tools accept neither commands nor arbitrary paths, URLs, credentials or pytest
arguments. Responses omit raw logs, payloads and machine paths. Evidence remains
under the selected sandbox data directory. The host controls when tools may run;
tool annotations describe behavior and do not replace the host's authorization.
Starting `target`, `openai` or `anthropic` can make a network request using the
previously configured profile. The offline operations remain separate and do
not start those checks implicitly.
Closing standalone MCP closes its owned workers; retained evidence is not deleted.
Closing the console bridge leaves the user-owned console running.

## Verify the actual stdio connection

After setup, run the SDK-environment smoke check, supplying your framework Python:

```bash
~/sandbox/enterprise-api-testing-framework/mcp/venv/bin/python \
  tests/mcp/stdio_smoke.py \
  --runner-python "$VIRTUAL_ENV/bin/python" \
  --output "$HOME/sandbox/enterprise-api-testing-framework/mcp-check-new"
```

Choose a new output directory each time. This check negotiates a real SDK stdio
connection, discovers tools, checks argument rejection and executes the contract
operation using the selected framework interpreter. It is separate from the
default core pytest suite because its SDK dependencies belong to another venv.

Protocol and SDK behavior follow the official
[Python SDK server guide](https://py.sdk.modelcontextprotocol.io/run/) and
[stdio client guide](https://py.sdk.modelcontextprotocol.io/client/transports/).
